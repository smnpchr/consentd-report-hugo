# Front-matter convention — consentd-report-hugo

This convention describes the YAML front matter of the Markdown files that
are generated by the Java generator (`HugoBookGenerator` in the consentd
project) and rendered by this repo's Hugo Book theme.

> **Status:** generalised sync (Source → Target instead of fixed THS → LIMS),
> single Hugo site with a Sync-Type → Sync-Run → Stage → Patient hierarchy.

## Design principles

- **All structured data lives in the front matter.** The Markdown body is
  minimal (just `# {title}`) and not intended for data transport.
- **Direct serialisation of the domain classes.** The front matter is
  largely the 1:1 Jackson serialisation of the Java domain records and
  classes (`BioBankConsent`, `ConsentEvaluation`, `DecisionRule`). There is
  no separate DTO layer; the field names match the Java component / property
  names.
- **Direction-neutral: Source / Target instead of THS / LIMS.** The sync
  fixes source and target; the front matter speaks of `source` and `target`
  throughout. THS/LIMS survive only as concrete *instances* (see Instance
  names).
- **Field names are camelCase**, like the Java components — with the
  exception of the map keys, which are ALL_CAPS_SNAKE_CASE (enum names from
  `ConsentModule`).
- **Hugo built-in fields** (`title`, `date`, `weight`, `bookCollapseSection`,
  `bookIcon`) follow the Hugo / Book theme convention.
- **Optional fields are omitted** (Jackson `NON_EMPTY` serialisation
  inclusion). A missing field means "not applicable" or "empty". In
  particular, empty maps and empty lists are absent from the YAML entirely.
- **Enum values are emitted as strings**, in their Java form (`AFFIRMED`,
  `INCONSISTENT`, `GRANTED`, `UNANSWERED`, `CXX_PROD`, etc.). Human-readable
  labels are translated by the theme via i18n — never written into the front
  matter as a resolved string (exception: `rule.description`, which is
  Java-resolved for historical reasons).

## Directory structure

A single Hugo site, four section levels under `content/reports/`:

```
content/reports/
  _index.md                    # Top: lists the sync types (static/minimal)
  daily/                       # Sync type — flattened section
    _index.md                  # Sync-type index  (SyncTypeIndex)
    2026-05-19/                # Sync run, e.g. "19.05.2026"
      _index.md                # Sync-run index   (SynchIndex)
      import/
        _index.md              # Stage index      (EvalStageIndex)
        <patientId>.md         # Detail           (EvalReport)
      operational/
        _index.md
        <patientId>.md
  weekly/                      # Sync type
    _index.md
    2026-week-21/
      _index.md
      compare/
        _index.md
        <patientId>.md
```

Each sync type (for example `daily` and `weekly`, more may be added) forms
its own section directly under `reports/`. Each sync run beneath it
**deliberately** creates a new section (named after `sync.title()`, e.g. the
date). The sync-run identity is therefore run-specific, not sync-stable —
this is intentional (history as side-by-side runs). The sync-type section is
flattened via `bookFlatSection` so the runs appear directly under the type
without an extra collapsible level.

## Four document types

### 1. Sync-type index — `<sync-type>/_index.md`

Written once per sync type (for example `daily` and `weekly`, more types may
be added). A pure grouping and structural node for all runs of a type; no
aggregates.

```yaml
---
title: "Daily report"
weight: 10
bookFlatSection: true
---
```

| Field | Type | Source / description |
|---|---|---|
| `title` | String | Application-configured label of the sync type |
| `weight` | int | Ordering of the sync types in the sidebar |
| `bookFlatSection` | boolean | Hugo Book flag, fixed `true`. Flattens the section — the sync runs appear directly under the type without an extra collapsible level. (Note: Hugo Book reads exactly `bookFlatSection`, not `flatBookSection`.) |

### 2. Sync-run index — `<sync-run>/_index.md`

Written once per sync run (in `finish()`, after all stages). A pure
structural node; aggregated numbers are supplied by the subordinate stage
indexes.

```yaml
---
title: "19.05.2026"
date: 2026-05-19T18:30:00+02:00
weight: 20260519
bookCollapseSection: true
---
```

| Field | Type | Source / description |
|---|---|---|
| `title` | String | `sync.title()` — run label (date / week) |
| `date` | DateTime with offset | Timestamp of the sync run |
| `weight` | int | `yyyyMMdd` format, for Hugo sorting |
| `bookCollapseSection` | boolean | Hugo Book collapsible-section flag. `true` for older runs (collapsed); the application sets `false` on the **most recent** run so it is expanded by default in the sidebar (see note below). |

### 3. Stage index — `<sync-run>/<stage>/_index.md`

Written once per sync run per `EvaluationStage`. Holds aggregates over all
patients of the stage and is at the same time the leaf summary (patient table
in the theme).

```yaml
---
date: 2026-05-19T18:30:00+02:00
weight: 20260519
bookCollapseSection: true
bookIcon: import
patientCount: 5
severitySuccess: 0
severityInfo: 1
severityWarning: 2
severityError: 1
severityCritical: 1
---
```

| Field | Type | Source / description |
|---|---|---|
| `date` | DateTime with offset | Timestamp of the sync run |
| `weight` | int | `yyyyMMdd` format, for Hugo sorting |
| `bookCollapseSection` | boolean | Hugo Book collapsible-section flag. `true` (collapsed) except on the primary stage of the most recent run, where the application sets `false` to surface it by default (see note below). |
| `bookIcon` | String | Icon name = `stage.name().toLowerCase()` (`import` / `operational` / `compare`), resolved via the `docs/icon` partial |
| `patientCount` | int | Number of evaluated patients |
| `severitySuccess` / `severityInfo` / `severityWarning` / `severityError` / `severityCritical` | long | Aggregate counter per severity |

**Label:** no `title` from Java — Hugo derives `.Title` from the folder name
(`import` → "Import"). The icon comes via `bookIcon` from the existing
`docs/icon` partial; the matching SVGs (`import`, `operational`, `compare`)
must live in the theme's icon directory.

**Default expansion:** the theme opens a collapsible section only when it is
the current page or an ancestor of it; otherwise it stays collapsed. To make
the freshest content reachable with the least effort, the application emits
`bookCollapseSection: false` for the most recent run and its primary stage —
the latest daily's `import` and the latest weekly's `compare` — so they render
expanded on the landing page (`bookCollapseSection: false` makes a section
non-collapsible and therefore always open). The whole chain down to the
patient table must be open, so **both** the sync-run index and that stage
index carry `false`; sibling stages (e.g. `operational`) and all older runs
keep `true` and stay collapsed.

### 4. Detail — `<patientId>.md`

Written once per patient per stage. Holds the full structured data of the
evaluation.

Complete example (canonical test fixture, daily sync THS → CXX_TEST):

```yaml
---
title: XXX
date: 2026-05-26T16:28:15+02:00
severity: critical
sourceName: THS
targetName: CXX_TEST
rule:
  name: NEW_AFFIRMED_THS
  stage: IMPORT
  source:
    timeValidity: VALID
    validityPeriod: EXPECTED
    aggregated:
    - AFFIRMED
  target:
    timeValidity: ANY
    aggregated:
    - EMPTY
  recency: ANY
  equality: ANY
  severity: INFO
  actions:
  - IMPORT
  - REPORT
  onFail:
    severity: CRITICAL
    actions:
    - REPORT
  stopEvaluation: false
  description: "Neuer bestätigter Quell-Consent, Ziel leer"
failureInfo:
  failureAction: IMPORT
  failureReason: "de.acme.common.exceptions.FailedImportException: 400 - Bad Request"
evaluation:
  sourceEvaluation:
    timeValidity: VALID
    validityPeriod: EXPECTED
    aggregated: AFFIRMED
    affirmations:
      NON_EU_TRANSFER: true
      ACQUIRE_USE_STOCK: true
      ADDITIONAL_ACQUISITION: true
      RETROSPECTIVE_USAGE: false
    content:
      NON_EU_TRANSFER: GRANTED
      ACQUIRE_USE_STOCK: GRANTED
      ADDITIONAL_ACQUISITION: GRANTED
      RETROSPECTIVE_USAGE: UNANSWERED
  targetEvaluation:
    timeValidity: NONE
    aggregated: EMPTY
  recency: SOURCE
  equality: NOT_EQUAL
consent:
  source:
    patientId: XXX
    origin: THS
    validFrom: 2025-08-11
    validUntil: 2055-08-11
    acquireUseStock: GRANTED
    additionalAcquisition: GRANTED
    retrospectiveUsage: UNANSWERED
    nonEuTransfer: GRANTED
    expired: false
---

# XXX
```

#### Top-level fields

| Field | Type | Description |
|---|---|---|
| `title` | String | Patient identifier |
| `date` | DateTime | Timestamp of the evaluation, ISO with offset |
| `severity` | String (lowercase) | Effective severity after OnFail: `success`, `info`, `warning`, `error`, `critical` |
| `sourceName` | String | Source instance (`InstanceName` name, e.g. `THS`, `CXX_PROD`) — from the sync endpoint, **not** from the consent |
| `targetName` | String | Target instance (`InstanceName` name, e.g. `CXX_TEST`) |
| `rule` | Object | The matched rule (see below) |
| `failureInfo` | Object, optional | Present only when an action failed |
| `evaluation` | Object | Evaluation result per side |
| `consent` | Object | Current consent state per side |

#### `rule` — matched rule

Direct serialisation of `DecisionRule`. Holds both the specification (what
the rule checks) and metadata (severity, actions, etc.).

| Field | Type | Description |
|---|---|---|
| `name` | String | Rule identifier (e.g. `THS_INCONSISTENT`). **Note:** rule names may still carry THS/LIMS in the identifier — that is the rule *identity*, not the direction semantics. Do not "correct" it. |
| `description` | String | From `RuleName.description()` (Java-resolved, locale-fixed) |
| `stage` | String | `IMPORT`, `OPERATIONAL` or `COMPARE` |
| `severity` | String (UPPERCASE) | Severity of the rule — may differ from top-level on OnFail |
| `actions` | List<String> | Actions to execute (`IMPORT`, `REPORT`, `INVALIDATE`, ...) |
| `recency` | String | Expected recency condition (`ANY`, `SOURCE`, `TARGET`, `EQUAL`, `NONE`) |
| `equality` | String | Expected equality condition (`ANY`, `EQUAL`, `AFFIRMATIONS_EQUAL`, `NOT_EQUAL`, `NONE`) |
| `source` | Object | `ConsentEvalDef` for the source side |
| `target` | Object | `ConsentEvalDef` for the target side |
| `sourceName` | String, optional | Instance filter of the rule (from `source-name` in the rule YAML); set only when the rule is restricted to an instance |
| `targetName` | String, optional | Instance filter of the rule (from `target-name`) |
| `onFail` | Object | Fallback configuration on action failure |
| `stopEvaluation` | boolean | Engine-internal flag |

#### `rule.source` / `rule.target` — eval def per side

Direct serialisation of `ConsentEvalDef`. Describes which conditions the rule
imposes on each side.

| Field | Type | Description |
|---|---|---|
| `timeValidity` | String | Expected validity (`ANY`, `VALID`, `EXPIRED`, `NONE`) |
| `validityPeriod` | String | Expected validity-term condition (`ANY`, `EXPECTED`, `DEVIATING`, `NONE`) |
| `aggregated` | List<String> | Allowed aggregation values. Wildcard: `[ANY]` |
| `affirmed` | Map<String, Boolean>, optional | For affirmation rules: target values per module |
| `content` | Map<String, String>, optional | For content rules: target values per module (`ModuleStatus` enum) |

`affirmed` and `content` are omitted for empty maps.

#### `failureInfo` — optional failure block

Direct serialisation of the `FailureInfo` record. Produced only when an
action threw an exception during the sync run.

| Field | Type | Description |
|---|---|---|
| `failureAction` | String | Which action failed |
| `failureReason` | String | From `ActionHandlerException.displayableReason()` |

#### `evaluation` — evaluation result

Direct serialisation of `RuleEvaluation`. The per-side evaluations are named
`sourceEvaluation` and `targetEvaluation` due to Java naming.

| Field | Type | Description |
|---|---|---|
| `sourceEvaluation` | Object | `ConsentEvaluation` for the source |
| `targetEvaluation` | Object | `ConsentEvaluation` for the target |
| `recency` | String | Actually determined recency relation |
| `equality` | String | Actually determined equality relation |

#### `evaluation.sourceEvaluation` / `evaluation.targetEvaluation`

Direct serialisation of `ConsentEvaluation`.

| Field | Type | Description |
|---|---|---|
| `timeValidity` | String | `VALID`, `EXPIRED`, `NONE` |
| `validityPeriod` | String | Whether the validity interval matches the expected term: `EXPECTED`, `DEVIATING`, `NONE` |
| `aggregated` | String | Aggregated evaluation value |
| `affirmations` | Map<String, Boolean>, optional | Per-module affirmation |
| `content` | Map<String, String>, optional | Per-module status |

`affirmations` and `content` are absent for an empty consent (no data
point) — the `NON_EMPTY` strategy drops them.

#### `consent` — current consent state

Wrapper record, grouping the two independent per-side consents for theme
convenience.

| Path | Type | Description |
|---|---|---|
| `consent.source` | `BioBankConsent`, optional | Source consent, if present |
| `consent.target` | `BioBankConsent`, optional | Target consent, if present |

#### `consent.source` / `consent.target`

Direct serialisation of `BioBankConsent` (Lombok `@Data` POJO). Omitted
entirely when the respective side has no consent.

| Field | Type | Description |
|---|---|---|
| `patientId` | String | Patient identifier (redundant with top-level `title`) |
| `origin` | String | Instance that supplied *this* consent (`InstanceName` name). Per-consent provenance — orthogonal to `sourceName`/`targetName` (endpoint identity). |
| `validFrom` | Date | Start of validity |
| `validUntil` | Date | End of validity |
| `acquireUseStock` | String | `ModuleStatus` enum value |
| `additionalAcquisition` | String | `ModuleStatus` enum value |
| `retrospectiveUsage` | String | `ModuleStatus` enum value |
| `nonEuTransfer` | String | `ModuleStatus` enum value |
| `expired` | boolean | Computed at the report's creation time |

> **No `originDescription`:** the human-readable instance description used to
> be written into the front matter. That has been dropped — only the enum key
> `origin` is emitted, and the theme resolves the description via `instance_*`
> (i18n).

## Status values

### `ModuleStatus` (module values)

| Value | Meaning | Source |
|---|---|---|
| `GRANTED` | Consent granted | THS + LIMS |
| `DECLINED` | Actively refused | THS + LIMS |
| `UNANSWERED` | Not ticked | supplied by THS (LIMS can't represent it) |
| `REVOKED` | Revoked | supplied by LIMS/CentraXX (THS can't represent it) |
| `UNAVAILABLE` | No data point present | THS + LIMS |

Additionally, the string `EMPTY` may appear as a front-matter marker — it is
not a `ModuleStatus` value but signals "the side did not supply this data
point at all".

### `ContentAggregation` (aggregation values in `aggregated` fields)

| Value | Meaning |
|---|---|
| `ANY` | Wildcard, only in `rule.*.aggregated` |
| `EMPTY` | Side is empty / has no consent |
| `INCONSISTENT` | Consent is internally contradictory |
| `DECLINED` | Fully declined (`fullyDeclined`) |
| `REVOKED` | Effectively revoked (`effectivelyRevoked`) |
| `AFFIRMED` | Load-bearing point affirmed (MII broad-consent semantics) |
| `CONSISTENT` | Wildcard-like match for any consistent variant |

### `TimeValidity`

| Value | Meaning |
|---|---|
| `ANY` | Wildcard, only in `rule.*.timeValidity` |
| `NONE` | No temporal information / no consent |
| `VALID` | Currently valid |
| `EXPIRED` | Expired |

### `ValidityPeriod` (validity-term match)

Per-consent check of whether the validity interval (`validFrom` →
`validUntil`) equals the expected term (exactly five years).

| Value | Meaning |
|---|---|
| `ANY` | Wildcard, only in `rule.*.validityPeriod` |
| `NONE` | Not determinable — `validFrom` and/or `validUntil` missing |
| `EXPECTED` | Interval matches the expected term (exactly five years) |
| `DEVIATING` | Interval differs from the expected term |

### `Recency` (recency relation)

| Value | Meaning |
|---|---|
| `ANY` | Wildcard |
| `NONE` | No side present |
| `EQUAL` | Source and target equally recent |
| `SOURCE` | Source is more recent |
| `TARGET` | Target is more recent |

### `Equality` (equality relation)

| Value | Meaning |
|---|---|
| `ANY` | Wildcard |
| `NONE` | No side present |
| `EQUAL` | Identical in content |
| `AFFIRMATIONS_EQUAL` | Equal at the affirmation level, not at the module status |
| `NOT_EQUAL` | Different in content |

## Instance names

`sourceName`, `targetName` (top-level) and `consent.*.origin` are all
`InstanceName` enum names:

- `THS`, `CXX_PROD`, `CXX_TEST`, ...

Two roles, the same enum:

- **`sourceName` / `targetName`** — identity of the sync *endpoint*. Fixed,
  even when the side has no consent (e.g. an empty target).
- **`consent.*.origin`** — provenance of *this particular* consent.

The human-readable descriptions come from the i18n YAML in the theme via
`instance_<NAME>` (e.g. `instance_CXX_PROD: "CentraXX"`); the Java
`InstanceName.description` is no longer authoritative for display.

## Module names (map keys in `affirmations` / `content`)

The map keys in `affirmations` and `content` are ALL_CAPS enum names from
`ConsentModule`:

- `ACQUIRE_USE_STOCK` — acquisition, storage, use
- `ADDITIONAL_ACQUISITION` — additional acquisition
- `RETROSPECTIVE_USAGE` — retrospective usage
- `NON_EU_TRANSFER` — non-EU transfer

At the POJO level (`consent.source` / `consent.target`), the field names are
camelCase instead: `acquireUseStock`, `additionalAcquisition`,
`retrospectiveUsage`, `nonEuTransfer`. This follows from the Java convention
(map keys via `ConsentModule.name()` vs. POJO properties via Lombok getters).

The theme's i18n keys cover both spellings.

## Body convention

The Markdown body is minimal — `# {title}` for detail pages, empty or minimal
for the index pages. All presentation happens in the theme from the front
matter; the heading and stage icon are supplied by the theme (`.Title` +
`bookIcon`), not the body.

If a second, platform-independent Markdown output is needed (e.g. for external
auditors without a Hugo stack), implement a dedicated `ActionCollector` with
its own generator — do not enrich this body.
